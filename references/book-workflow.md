# 整套扫描书籍优化

按用户当前请求组合步骤，不把全流程强加给只读审计或元数据修改。下列是端到端任务的编排参考。

## 1. 建立范围与基线

记录每册原件、已有成品、页序与质量目标。前几册已处理、要求后几册沿用时，提取前册实际参数与效果，只为新增/异常页补证据。区分保留原件、另存输出和覆盖旧成品；备份规则见 [备份与清理](backups-and-work-files.md)。

先读审计：主要开销是 RGB 扫描、灰阶、透明蒙版还是文字形状？黑白外观不代表真的只有二值像素；JPEG 的灰边、纸纹和连续灰阶都需要判断。记录通道关系、灰阶直方图、蒙版与颜色配置，不能仅凭肉眼判定“没有灰阶”。

## 2. 几何与代表页

跨册选正常正文尺寸，保留有意义的横版；巨大封面框与异常旋转单独处理，见 [页面几何](page-geometry.md)。先确定几何再检查压缩样本，避免把几何已改变的旧显示证据复用到新版本。

样本覆盖正文细笔画、最密集页面、灰字/灰条、插图、照片、封面和异常页。以原生网格编码，不为节省实现成本整书重采样。

## 3. 分页压缩与两版取舍

纯黑白正文优先比较原生 G4 与 generic JBIG2。少量真实中间灰值可做独立保护；连续灰阶、照片和彩色块保留或使用经授权的 MRC 策略。详见 [分层与修复](segmentation-and-repairs.md)。

封面、书名、版权、封底各自判断，不能因为处在附属位置就一律 JPEG。可试验约 300 dpi、JPEG quality 88 的彩色封面，但这些是样本参数，会改变原始像素；不是标准要求，也不是无损处理。正文不套用封面策略。

记录两版总大小、主要码流、代表页解码时间与阅读器体验。离线同 DPI 耗时不能直接保证 UI 翻页快；未测速度时直接以编码器命名更诚实。

## 4. 导航与页码

压缩保持页序后可直接沿用已确认的物理页映射。按 [导航与标签](navigation-and-labels.md) 补原书目录层级及实际附属页，书签用“书名”“版权”。仅第一册有版权时不要在其他册空白页上设置版权。保留用户手改书签，标签任务单独执行。

## 5. 验证、证据与交付

| 当前变化 | 可复用 | 新检查范围 |
|---|---|---|
| 仅标签/书签 | 正文编码、已有画面检查 | 显式计划与段界/目的页，按用户要求可跳过 |
| 几何 | 原图像素/编码证据 | 新框、矩阵、方向和相应交互/显示 |
| 编码不改目标像素 | 原内容分类 | 实际原生位图、极性、结构和独立渲染 |
| 二值化/降采样/灰条修复 | 未触及区域证据 | 改动区域质量及边界、代表页，不称原扫描严格无损 |
| 严格无损任务 | 仅同一基准可复用的证据 | 全页/资源比较与明示特征范围 |

报告验证了什么、未做什么；用户明确不要检查时直接按授权修改，记录跳过，不借旧报告冒充当前验证。书签更新后的整个 PDF 哈希必须重算或标为未重算；图像未变的原生编码证据仍可复用。

编码缓存以原生图内容、有效属性、参数、算法与工具版本为键；渲染缓存还需页面几何、颜色设置及渲染器版本。并发从内存预算出发，单页试测后再增加，不能只按 CPU 核数开 worker。

处理说明通常只写“做了哪些处理”：几何、压缩/近似范围、导航、标签及实际验证。不要夹带机器路径、存储位置、工作目录、完整目录树、文件索引或日志转储。回复可另外链接实际成品。用户满意后按明确范围清理可重建材料；删除备份需要用户指明，删除后不另建隐藏恢复包。
