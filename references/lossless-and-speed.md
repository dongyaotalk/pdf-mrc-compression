# 无损优化与渲染速度

## 确定基准和体积来源

记录基准文件哈希。相对一个已经二值化、降采样或统一底纹的 MRC 版本无损，不等于相对原始扫描无损。

按唯一 xref 统计编码字节，分别看文字蒙版、背景、前景颜色、图片/封面、透明蒙版和其余结构。不要按出现页数重复计算共享书衣。若主要是文字蒙版，优化 JPEG 不会带来同样收益；若主要是照片，继续分割正文可能没什么空间。

## 优先尝试的画面不变优化

### 结构整理

清除不可达对象，合并确实等价的对象，压缩内容流和对象流。不要删除 OCR、书签、链接、ICC、附件或表单来冒充无损压缩。

```bash
qpdf --object-streams=generate --recompress-flate --compression-level=9 input.pdf output.pdf
qpdf --check output.pdf
```

保留输入，输出到不同路径；记录 PDF 版本和目标阅读器兼容性。结构空间有时只有几十到几百 KB，先测再决定是否值得保留额外版本。

### JPEG 熵编码

对提取的原 JPEG 码流使用 `jpegtran -copy all -optimize`，不重新量化、不降采样。替换 PDF 图像流时保留有效的 `/ColorSpace`、`/Decode`、`/DecodeParms`、ICC 和显示矩阵，并验证解码像素。

只应用比原码流更小的结果。渐进 JPEG 不一定更小，也可能增加内存或解码成本；不要以“转渐进式”代替测量。PNG 转 JPEG、降低 quality、删除扫描颗粒都不是严格无损优化。

### 前景常量与真灰度

- 若整张前景颜色图每个像素确实相同，改为 1×1 色块并保留全分辨率形状蒙版，可节省体积和颜色图解码。检查整幅颜色图；不能仅因看起来黑就假设恒定。替换后验证渲染和原文字蒙版。
- 若 RGB 解码结果处处 R=G=B，可尝试灰度表示。在已验证的 JPEG 情况下，`jpegtran -grayscale -optimize` 保留亮度 DCT，去掉无用色度；转换后仍必须比较实际解码像素并正确更新颜色空间。
- RGB 通道相等不自动证明 ICC、CMYK、Decode 或颜色管理后的灰度转换等价。涉及这些情况应保留原配置或用规范的颜色管理验证，不盲目改为 DeviceGray。

### 资源复用

相同图像、底纹、ICC 和遮罩尽可能共用资源引用。判断等价时考虑尺寸、位深、颜色空间、Decode、蒙版、插值、解码参数等有效属性；单凭 JPEG/PNG 文件名或裸流哈希不足以合并对象。

同一资源可在各页用不同矩阵、裁剪和透明度显示。复用不会保证阅读器只解码一次；跨页缓存行为仍需实测。

## 文字蒙版：G4 与 JBIG2

CCITT Group 4 和 JBIG2 generic 都可以无损编码二值位图，结果取决于笔画、噪声和编码器。比较实际文件及实际阅读器性能。

- 用 `jbig2enc` 的 `jbig2 -p -d` 生成 PDF 可用的 generic 位图码流，不用符号字典匹配模式 `-s`。这里的“无损”要求原生解码蒙版逐像素一致，不能仅依赖编码器选项名称。
- 不把 `-r` 当作所有版本都可靠的无损符号细化开关。曾检查的 0.32 实现存在相关实现/兼容性限制；如果考虑其他版本，先核实实现并证明所有字形像素一致。
- `/JBIG2Decode`、`/CCITTFaxDecode`、`/Decode`、`/ImageMask`、`BlackIs1` 等决定极性。改 Filter 时移除过期参数，保留仍有效的参数；没有 globals 的 generic 码流不能挂着旧 `/JBIG2Globals`。
- 从 TIFF 提取 G4 原始数据时，不能把多个 strip 直接拼成一个单流。确认编码器使用单 strip，或正确处理分条；设置匹配的 K、Columns、Rows、BlackIs1、EndOfBlock。最终以解码位图为准。

### 只裁剪编码区域，保留全画布

大片空白可不参加 generic 区域编码，但 PDF 蒙版的全幅尺寸、图像原点和整数像素位置保持不变。随附 `encode_jbig2_region.py` 为这个用途生成标准 Page Information + Immediate Generic Region 段。

它适用于真正黑白二值图，输入黑色为墨迹、白色为纸底。脚本拒绝灰度中间值，不会暗中再次阈值化。空白图、极小图和单像素图都要正确处理；输入编码器时使用 1-bit PNG，避免极小 PBM 头太短导致部分 Leptonica 版本读取失败。

该优化依赖可识别的编码器段布局。脚本检查段类型、长度、引用和组合规则，结构不符就停止；不能套用固定字节偏移到未知码流。嵌入 PDF 时保留完整 Width/Height，并验证蒙版本身和页面渲染。

分块/分带可以缩小每次解码区域，但也会丢失编码上下文、增加段数。历史测试中 64–512 像素条带常比单个包围盒更大，速度也未稳定超过 G4；只对当前样本测量，不作为全书默认配置。

## 翻页慢的排查顺序

1. 查原生图像数量、面积、解码格式、冗余透明层和重复绘制。整页 1200 dpi 蒙版、多层软透明和巨幅书衣，即使最终文件很小，也可能很慢。
2. 合并兼容的文字形状层，统一同一段文字的颜色场，去除已经被新内容替代的旧绘制。不能合并不同颜色/透明度/混合语义的图层。
3. 常量前景改小色块；仅在真正需要灰阶边缘的区域用软蒙版，纯二值形状使用二值蒙版。
4. 对比原生 G4、generic JBIG2 和保留原扫描的方案。不要只比较码流大小。
5. 巨幅图即使只裁剪显示一小块，也可能需要解码整幅。要减少解码面积，需要重新组织图像；如果改变 JPEG 裁剪边界或重编码，重新验证质量边界。

若最小文件明显较慢，可保留快读版，另提供紧凑版。未经测量不宣称优化了首屏或 UI 翻页；离线渲染耗时只是相同条件下的解码比较。

## 验证分层

**严格无损相对当前版本：**

- 原文件哈希不变，页数、MediaBox/CropBox、旋转、书签、OCR、链接等保留。
- 被改编码的图像和蒙版逐个比较原生解码像素；涉及颜色空间时比较等价颜色表示及渲染。
- 全书同 DPI、同渲染器、同颜色空间逐页精确比较；另用 Poppler 在不同 DPI 抽查封面、灰条、公式、插图和旋转页。
- `qpdf --check` 通过仅代表结构检查，不代表画面、颜色或字形正确。

**视觉近似或局部修复：** 记录允许改变的区域，比较区域外是否保持一致；目视检查区域内颜色、字重、断笔、粘连、细线和边界。平均 SSIM/PSNR 不能证明公式没有丢一个负号。

**计时：** 说明 DPI、渲染器、页码范围及冷/暖缓存条件；用相同设置并交替顺序，分别记录基准和输出耗时。不要把不同轮测试或不同 DPI 的绝对秒数混在一起。

PyMuPDF 中 `Pixmap.samples_mv` 的内存视图依赖 Pixmap 存活。先保留 `pix = Pixmap(...)` 再哈希 `pix.samples_mv`，不要从立即释放的临时 Pixmap 取内存视图；大页尽量避免额外复制全部 RGB 字节。
