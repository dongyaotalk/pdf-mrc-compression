# 备份与工作文件位置

## 持久备份放在输入 PDF 旁边

原件不变、另存新成品时，不必额外复制整本原件。需要原地修改或替换已有 PDF
（例如添加书签、修改页码标签）时，先把被修改文件备份到其同级的可见
`pdf-mrc-backups/` 目录。批量文件分别使用各自的输入目录，不以当前工作目录、
skill 安装目录或代码仓库作为备份根目录。

推荐调用随附的标准库工具；它保留文件名，为每次调用创建独立的阶段目录：

```text
python scripts/backup_pdf.py "books/扫描资料.pdf" --stage before-bookmarks
```

```text
books/
  扫描资料.pdf
  pdf-mrc-backups/
    20261110T040000.000000Z-before-bookmarks-<unique-id>/
      扫描资料.pdf
      backup.json
```

工具不会编辑 PDF，也不解析或重编码其内容。它复制字节、独立回读校验大小与
SHA-256、检查复制期间输入未变，再写出 `backup.json`。记录包含输入路径、
备份路径、阶段、UTC 时间、字节数和哈希，命令成功后在标准输出报告这些信息。
阶段名使用 1–40 个 ASCII 字母、数字、连字符或下划线，以兼容不同平台。
文件名中的中文和空格保持不变。每次调用产生独立副本，重复调用不覆盖旧备份，
也不创建会随原地修改一起变化的硬链接。

自写处理脚本应先调用 `backup_pdf(input_path, stage)`，成功后才进入 PDF 写入阶段；
也可以先执行 CLI 并检查退出码。返回 `0` 表示备份完成，`1` 表示备份失败，
`2` 为命令行参数错误。备份工具只需要 Python 3.10+ 标准库。

## 写入与交付

- 备份失败时停止后续 PDF 修改，报告原目录权限、空间或其他错误；不悄悄改存
  `.mrc-work/`、用户隐藏目录、仓库或 skill 安装目录。
- 自写编排也必须遵守上述位置规则。不得把持久备份混入编码缓存，或用硬链接
  充当原地修改前的独立副本。
- 交付时明确列出成品与备份位置，说明保留了哪些阶段及其大致占用，便于用户管理。
- `backup.json` 可能含本机路径，随备份留在用户目录，不提交到公开仓库。
- 不自动清理或搬迁既有备份。若用户要求整理历史隐藏工作目录，先核对备份、
  成品及当前任务引用，再在其授权范围内处理。

## 可重建缓存

图像分层、JBIG2/G4 编码缓存、渲染预览、日志和验证报告属于不同用途。
可重建工作文件可以使用任务工作目录，但不能把它当作原始 PDF 的唯一备份位置。
记录实际工作目录及清理条件；缓存使用输入哈希和算法参数区分，避免误复用旧结果。

## 连续任务不重复复制整本基线

`normalize_pages.py`、`compress_scans.py`、`set_navigation.py` 默认另存新输出；覆盖已经存在的目标（含原地修改）才备份。多个连续修改可共用 `--session work/session.json`：记录已验证基线及本次写入后文件哈希，下次仅在当前文件仍匹配、可见备份仍存在且回读哈希一致时复用。外部手动修改、基线丢失或记录不匹配则重新备份。不要在不同任务之间无限复用旧 session；session 不是备份本身。

工具原子写出 PDF，不要求为每次书签/标签微调再复制数 GB。默认保留既有备份，不由优化操作自动删除。用户清理备份的明确指令优先：连同指定的恢复包、备份清单和过期说明删除，不再偷偷创建新的隐藏备份。

## 有范围的清理计划

```bash
python scripts/cleanup_outputs.py books --plan cleanup.json
python scripts/cleanup_outputs.py books --plan cleanup.json --apply
```

```json
{"keep": ["处理说明.md"], "delete_backups": []}
```

默认预览，`--apply` 才实际清理根目录下的非 PDF 文件和可删除的空目录。大小写不敏感保护 `.pdf`；`keep` 可指定文件或整个子目录。`pdf-mrc-backups/` 及其清单默认整体保护；符号链接保留，不跟随到外部目录。

用户同时要求删除备份时，显式列出该目录内的恢复材料：

```json
{"keep": ["处理说明.md"], "delete_backups": ["pdf-mrc-backups", "task-recovery.zip"]}
```

`delete_backups` 是准确的相对路径清单，不用全盘 glob，不允许越出目标根目录，不与保留项重叠。若目标包含多本书，仅列当前任务的备份子目录，不能删除别的书的基线。根目录以外的任务缓存/恢复材料须作为另一次有明确根目录的操作处理。工具不写恢复副本，也不自动重写保留说明。

处理说明默认仅记实际操作及近似/验证范围，不记录目录位置、机器路径、缓存、完整书目目录或日志。删除备份后同步撤下本任务仍声称“可恢复”的过期清单；不要把历史记录的存在误当备份仍在。
